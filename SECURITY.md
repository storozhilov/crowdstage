# Security Policy

## Supported versions

CrowdStage is under active early development. Until the project publishes a supported-version policy, assume that only the latest code on the default branch is being reviewed for security issues.

## Reporting a vulnerability

Please do **not** report security vulnerabilities in public GitHub issues.

Use GitHub's **Report a vulnerability** feature on the repository's Security tab, if enabled. If private vulnerability reporting is not enabled yet, contact the maintainers privately using the contact information published in the repository profile.

Include:

- A description of the issue and its potential impact.
- Steps to reproduce or a proof of concept, if safe to provide.
- Affected commit, release, component, or deployment configuration.
- Any suggested mitigation.

Please allow maintainers reasonable time to investigate and coordinate a fix before public disclosure.

## Secrets and personal data

Never include real access tokens, API secrets, credentials, private guest media, or personal data in issues, logs, screenshots, or pull requests. Redact sensitive values before sharing diagnostic output.
